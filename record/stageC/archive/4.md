Step 1: 换框架——从 EM 换到 Correspondence-Based
我之前一直在 EM 框架里打转。重想一下，发现一个更契合我们 setting 的思路：用 DiT 特征做跨 state 对应匹配，然后从对应点直接反推 rigid motion。

为什么 EM 不是最优：

EM 需要同时估计 assignment + axis + transforms，耦合高，迭代慢
对初始化敏感（v1 的 variance split 初始化就垃圾）
Voxelization aliasing 和 TRELLIS 噪声下 EM 收敛不一定到正确局部极小
为什么 feature correspondence 更 elegant：

DiT feature 已经编码了 "这个 voxel 是什么材料/语义"（这是 M_attn 能 work 的根本原因）
同一个物理点（比如抽屉面中心）在不同 state 下 DiT feature 接近（因为语义一致）
不同物理点（比如抽屉面 vs 柜体侧板）feature 远
所以：跨 state 找对应 = 找 feature 最接近的 voxel
一旦有了 N 对对应点，rigid transform 是闭式解（SVD / Kabsch，Arun et al. 1987）
这完全避开了 EM，转化为一个特征匹配 + 刚体拟合 + 聚类的经典 pipeline——每一步都是 CV 成熟技术。

Step 3: 具体算法 —— SegMatch
═══ C.1 Pre-segmentation (reuse Stage B M_attn) ═══
# 不要重新做分割，用 M_attn 直接分
for each state k:
    base_k  = (O_stack[k] > 0.5) ∧ (M_attn_64 > τ_base)       # high semantic agreement
    move_k  = (O_stack[k] > 0.5) ∧ (M_attn_64 < τ_move)       # low semantic agreement
    amb_k   = rest                                             # 待定 voxel, C.5 处理
# τ_base = 0.7, τ_move = 0.3 → 高置信区直接用，中间灰带放后面
═══ C.2 Cross-state feature correspondence ═══
# 用 z_final 的特征在每个 move voxel 找跨 state 对应
# z_final shape: (K, 8, 16, 16, 16). 把它上采样到 64³ 特征（trilinear）
# z_final_64 shape: (K, 8, 64, 64, 64)
# Reference state = state 0. 对每个 move_0 里的 voxel v:
for v in move_0.nonzero():
    feat_v = z_final_64[0, :, v]                              # (8,) reference feature
    # 在 state k 里找特征最近 + 空间邻近的 voxel
    for k in 1..K-1:
        candidates = (move_k ∪ amb_k) ∩ spatial_window(v, r=window_size)
        if candidates.empty:
            corr[v][k] = None   # 不可见, skip
            continue
        sims = cosine(z_final_64[k, :, candidates], feat_v)
        best = candidates[argmax(sims)]
        corr[v][k] = best        # 跨 state 对应的 voxel 位置
# corr: dict {v_in_canonical: [v_in_state_1, v_in_state_2, ..., v_in_state_K-1]}
# 一些 voxel 可能在某些 state 不可见 (None),allow
# 注意: window 机制防止长距离 feature 误匹配; r 一般是 6-8 voxel
═══ C.3 Motion trajectory → part clustering (multi-joint discovery) ═══
# 对每个有对应的 v, 提取 displacement 序列
trajectories = {}
for v, matches in corr.items():
    displacements = []
    for k, v_k in enumerate(matches):
        if v_k is None: continue
        displacements.append(v_k - v)       # 3D 位移
    trajectories[v] = displacements
# Part clustering via trajectory similarity
# 如果 prismatic: displacement vector 与 axis 平行, magnitude ∝ joint param
# 如果 revolute: displacement = R_k @ v - v; 不是单一向量
# 
# 关键: 同一个 part 的 voxel, 它们的 k 步位移集合应该 consistent with 同一刚体运动
# 做法: 用 "per-voxel displacement signature" 聚类
# 最简单: 对 state k 的平均位移做 spatial k-means
# 更好: 对每个 voxel, 拟合 "它可能所在的 rigid transform" 的参数空间, 聚类
# Pragmatic 实现:
# Step 3.1: 对每个 voxel 的 trajectory (list of displacements), 用 PCA 取主方向
# Step 3.2: 在主方向空间做 DBSCAN 聚类 (不需要预设 P)
# Step 3.3: 每个 cluster → 1 个 part; outlier → base 或 discard
═══ C.4 Per-part rigid transform fit ═══
# 对每个 part p, 用它的 correspondences 拟合 per-state T_k^(p)
for p in parts:
    for k in 1..K-1:
        # Kabsch SVD: 闭式解 rigid transform
        src = v_canonical_in_part_p
        tgt = v_in_state_k corresponding
        T_k^(p) = kabsch(src, tgt)        # 4x4 SE(3)
    # BIC revolute vs prismatic based on residual
    # Revolute: T 应该可参数化为 (axis, angle_k)
    # Prismatic: T 应该可参数化为 (direction, distance_k)
    # Fit both, compare BIC
    joint_type_p, axis_p = bic_select(T_k^(p))
═══ C.5 Ambiguous voxel reassignment ═══
# amb_k 里的 voxel: 看它和哪个已确认的 category 最 compatible
for v in amb_k:
    # 测试: 假设 v 是 base, 它在 state k 的预期位置 = v (不变). Match O_k(v)?
    score_base = cross_state_consistency(v, identity)
    # 测试: 假设 v 是 part p 的 move, 它在 state k 的预期位置 = T_k^(p)(v). Match O_k?
    for p in parts:
        score_move_p = cross_state_consistency(v, T_k^(p))
    assign v to argmax(scores)
═══ C.6 Canonical aggregation (output for Stage D) ═══
canonical_base = OR over k of base_k                    # 跨 state 并集, 填补遮挡
canonical_move_p = OR over k of T_k^(p)^(-1)(move_p_k)  # 逆变换到 canonical 再并集
# Contact region for each part (Stage D 用)
contact_p = dilate(canonical_base, 1) ∩ canonical_move_p
# Output pack (exactly what Stage D needs)
stage_c_output = {
    "canonical_base"        : canonical_base,         # (64, 64, 64)
    "canonical_move_parts"  : [
        {
            "volume"               : canonical_move_p,
            "axis"                 : (origin, direction),
            "type"                 : "revolute" | "prismatic",
            "per_state_transforms" : [T_0, T_1, ..., T_{K-1}],
            "per_state_params"     : [θ_k or d_k for k in 0..K-1],
            "contact_region"       : contact_p,
        } for p in parts
    ],
    "per_state_assignment"  : (K, 64, 64, 64) int,    # Stage D 用来知道每个 voxel 在每个 state 是什么
}
Step 4: 为什么这个设计好（第一性 + AAAI-worthy）
第一性原理上
信息流最短：Stage B 的 DiT feature → cross-state similarity → rigid transform → canonical aggregation。没有迭代 EM，每步都是闭式或局部解。
解耦：segmentation, correspondence, rigid fit, part discovery 是正交的，一个步骤错不会级联损坏下一个（EM 会）。
Multi-joint auto-discover：不预设 P，用 trajectory clustering 发现。这在 2-state 方法（PARIS）里做不到。
对 AAAI 审稿人
Novelty: "First zero-shot articulated motion segmentation via diffusion feature correspondence"
Technical depth: 涉及 feature learning, rigid registration, motion segmentation, 每个都有文献锚点
Practical impact: training-free，不需要 joint dataset（这是 A-SDF / CAGE 的限制）
Clean extension: Stage D 的 MorphAny3D texture inpainting 直接拿 canonical geometry，pipeline 紧凑
Ablation 丰富:
with/without M_attn prior
feature matching vs variance-based
trajectory clustering vs predefined P
Kabsch vs differentiable registration
和 PARIS / MorphAny3D 的差异化
维度	PARIS	MorphAny3D	Ours
Input	2 images	2 3D shapes	K=6 images
Joint inference	Optimize SDF+joint	不做	Feature corresp + Kabsch
Multi-joint	受限	N/A	Auto discovery via clustering
Training	No (optim-based)	No	No (feature-based, closed-form)
Speed	分钟级（优化）	秒级	秒级（SVD / k-means）
Texture	No	Via SDS	Via MorphAny3D-inspired inpaint (Stage D)
