# Pipeline: RASA-TRELLIS for Single-Image Articulated 3D Asset Generation

**Version:** 2026-04-26  
**Target venue standard:** AAAI-level novelty, reproducibility, and ablation clarity  
**Working title:** **RASA-TRELLIS: RFSDS-Optimized Articulated State Adapters inside Frozen TRELLIS**

---

## 0. Executive Summary

We aim to generate an articulated 3D asset from a **single closed-state image**. The output should contain:

- a canonical static **base**;
- a canonical **movable part**;
- a single-DoF **prismatic or revolute joint**;
- state-consistent geometry and texture;
- an exportable mesh / Gaussian / radiance representation and URDF-style joint metadata.

The core design is:

1. Use **Wan2.2 I2V-A14B** to generate a fixed-camera opening video from the single input image.
2. Extract **K pseudo-state frames** from this video and use them as **K image conditions** for frozen TRELLIS.
3. Insert trainable, zero-initialized **RASA adapters** into frozen TRELLIS SS-DiT and SLAT-DiT.
4. Use SS-RASA to infer base/move logits and single-DoF joint variables inside the sparse-structure generation process.
5. Use SLAT-RASA, inspired by MorphAny3D-style attention fusion, to fuse cross-state appearance and newly exposed texture inside SLAT-DiT.
6. Use **Wan2.2 W-RFSDS** as a frozen fixed-camera video prior to optimize the newly added adapters, part logits, joint trajectory, support gates, and texture variables.
7. Use NANO3D-inspired region-aware merging at both SS and SLAT levels to make the base invariant while allowing the movable part to change.

The central claim is not that TRELLIS already contains explicit articulated part labels. The defensible claim is:

> TRELLIS has spatially localized editable SLAT/DiT representations, as evidenced by local manipulation and asset variants. We convert that latent locality into articulated base/move/joint structure through K-state pseudo conditions, in-loop cross-state adapters, region-gated merging, and Wan2.2 W-RFSDS optimization.

## 1. Research Goal

### 1.1 Input

A single RGB image of an articulated object in a mostly closed or resting state:

```text
I0: one closed-state input image
prompt: locked-camera articulation prompt, e.g. "a drawer slides open" or "a cabinet door rotates open"
```

### 1.2 Output

```text
canonical_base_mesh.glb
canonical_move_mesh.glb
object.urdf
joint.json
texture_provenance.json
optimized_fixed_camera_video.mp4
intermediate diagnostics
```

### 1.3 Core constraints

- Single observed image only.
- K additional frames are generated by Wan2.2 and must be treated as **pseudo-state conditions**, not real observations.
- TRELLIS original weights remain frozen.
- Wan2.2 original weights remain frozen.
- Only our inserted neural modules and continuous latent variables are optimized.
- Joint model is initially limited to **single-DoF prismatic or revolute**.
- Base consistency is enforced by architecture-level tying / merge, not by soft regularization alone.

## 3. High-Level Pipeline

```text
Input single image I0
        │
        ▼
[Phase 0] Wan2.2 fixed-camera pseudo-state video generation
        │
        ├── Extract K frames: I0, I1, ..., I_{K-1}
        └── DINO/TRELLIS image conditions: cond_K
        │
        ▼
[Phase 1] Frozen TRELLIS SS-DiT + in-loop SS-RASA
        │
        ├── K-state sparse-structure generation
        ├── cross-state part slots
        ├── base / move / uncertain logits
        ├── prismatic / revolute joint variables
        ├── SS-level soft base tying
        └── fixed-support differentiable gate
        │
        ▼
[Phase 2] Frozen TRELLIS SLAT-DiT + SLAT-RASA
        │
        ├── K-way MCA for donor image-condition fusion
        ├── K-way TFSA for cross-state SLAT consistency
        ├── Slat-Merge-style region-aware texture fusion
        └── exposed texture / interior detail refinement
        │
        ▼
[Phase 3] Differentiable rendering + Wan2.2 W-RFSDS
        │
        ├── high/mid noise: geometry, part, trajectory
        └── low noise: texture, detail, temporal consistency
        │
        ▼
[Phase 4] Hard export
        │
        ├── hard base copy
        ├── mesh / 3DGS / radiance decode
        ├── joint.json / URDF
        └── diagnostics and ablations
```

## 4. Phase 0: K Pseudo-State Condition Generation

### 4.1 Purpose

The single closed-state image does not directly reveal the opened geometry, exposed interior, or motion range. Wan2.2 I2V-A14B provides a fixed-camera pseudo opening sequence.

### 4.2 Procedure

1. Input the original image `I0` and a locked-camera prompt.
2. Generate a Wan2.2 I2V video.
3. Select K temporally ordered frames:

```text
I_0 = original / first frame
I_1, ..., I_{K-1} = pseudo opened states
```

4. Encode all K frames using TRELLIS image conditioning pipeline, normally DINOv2-based visual tokens:

```text
cond_K = DINOv2([I_0, ..., I_{K-1}])
```

### 4.3 Prompt template

```text
A locked-off single-camera video. The first frame is exactly the provided image.
The camera is static: no zoom, no pan, no orbit. The object body remains stationary.
Only the movable part opens with a physically plausible single-DoF motion.
The material, color, lighting, and texture remain consistent across all frames.
Newly revealed interior surfaces are coherent with the object's material.
```

### 4.4 Negative prompt

```text
camera movement, zoom, pan, orbit, changing identity, changing background,
object morphing, non-rigid deformation, texture flicker, floating pieces,
body moving, new object appearing, scene cut
```

### 4.5 Important qualification

K frames are **pseudo-state conditions**, not ground-truth observations. They may contain hallucinated surfaces or incorrect motion. The method must therefore retain frame confidence and RFSDS validation rather than forcing exact reconstruction of every pseudo frame.

## 5. Phase 1: SS-RASA for Geometry, Part, and Joint

### 5.1 Goal

Generate K coupled sparse structures while extracting:

- canonical base probability;
- canonical movable-part probability;
- uncertain / residual probability;
- single-DoF joint variables;
- fixed support and differentiable support gates.

### 5.2 Frozen TRELLIS SS-DiT with inserted adapters

We do not train original TRELLIS weights. We insert zero-initialized trainable residual adapters into selected mid-late SS-DiT blocks.

Default blocks:

```text
SS-RASA blocks = {16, 19, 22}
```

Ablation blocks:

```text
{12, 16, 20}
{8, 12, 16, 20}
SS only vs SS+SLAT
```

### 5.3 SS-RASA-Core modules

The main adapter contains:

1. **same-voxel cross-state attention**: token index `l` attends across K states only;
2. **part-slot bottleneck**: base/move/uncertain slots pool voxel features and scatter part-aware residuals back;
3. **frame confidence gate**: discounts unreliable Wan-generated pseudo frames;
4. **region-gated residual**: base residual is heavily anchored, move residual is allowed to vary;
5. **zero-init residual scale**: iteration 0 is identical to frozen TRELLIS.

### 5.4 PartHead

A dual-resolution part head is required:

```text
16^3 semantic branch:
  SS-DiT multi-tap features → coarse base/move/uncertain logits

64^3 boundary branch:
  SS-VAE decoder features / occupancy logits → boundary correction

fusion:
  part_logits_64 = upsample(part_logits_16) + gamma * boundary_logits_64
```

### 5.5 JointHead

Single-DoF candidates:

- **Prismatic**: direction `a`, scalar displacement `d_k`.
- **Revolute**: axis `a`, pivot/origin `o`, angle `theta_k`.

Recommended paper version:

```text
axis = S^2 bin classification + residual refinement
trajectory = monotonic q_k sequence
joint type = prompt-specified or two-branch model selection
```

### 5.6 SS-level NANO3D-style base tying

NANO3D preserves unedited regions by Voxel-Merge. We reinterpret:

```text
unedited region = base
edited region   = movable part
```

Training-time soft tying:

```text
z_SS_tied[k] = m_move * z_SS_raw[k] + (1 - m_move) * z_SS_raw[0]
```

Export-time hard tying:

```text
if move_prob < threshold:
    z_SS_final[k] = z_SS_final[0]
```

This guarantees bit-identical base at export while keeping training differentiable.

## 6. Phase 1.5: Fixed-Support Differentiable Gate

TRELLIS extracts SLAT support coordinates by hard threshold and `argwhere`, which is non-differentiable. We do not modify this operation or claim it is differentiable. Instead, we use a fixed-support relaxation.

### 6.1 Support initialization

Build a conservative support canvas once, no gradient:

```text
SUPPORT_COORDS =
    union_K occupied coords
  ∪ dilation(union_K occupied coords)
  ∪ top-K uncertain boundary coords
  ∪ motion-sweep candidate coords from predicted joint
```

### 6.2 Differentiable gate

At each optimization iteration, recompute current SS logits and sample them at fixed support coordinates:

```text
g_i = sigmoid(SS_decoder(z_SS_current)[SUPPORT_COORDS_i] / T)
```

This gate controls:

- SLAT feature magnitude;
- Gaussian opacity;
- SDF margin;
- texture adapter routing.

Thus RFSDS gradients can flow through:

```text
render → support gate → SS decoder logits → SS latent → SS-RASA
```

## 7. Phase 2: SLAT-RASA for Cross-State Texture and Detail

### 7.1 Motivation

TRELLIS SLAT contains local geometry and appearance. MorphAny3D shows that source/target SLAT features can be fused inside attention mechanisms using MCA and TFSA. We adapt this from two-endpoint morphing to K-state articulated fusion.

### 7.2 SLAT-RASA modules

1. **K-way MCA**: each donor state image condition is cross-attended independently, then attention outputs are fused.
2. **K-way TFSA**: self-attention uses cached donor state features to improve temporal / cross-state consistency.
3. **region-gated Slat-Merge**: base SLAT tokens are anchored to state 0; move and exposed tokens use donor-weighted fusion.
4. **texture adapter**: small AdaptFormer-style or residual appearance adapter for color/detail refinement.

### 7.3 Donor routing

For target state `k`, token `i`, donor state `j`, donor weight depends on:

```text
visibility(i, j)
part compatibility(i, j)
frame confidence(j)
temporal proximity(k, j)
RFSDS reliability(j)
```

Rules:

- base tokens prefer state 0 and high-consistency donors;
- move exterior tokens prefer states where the moving part is visible;
- newly exposed interior tokens prefer opened states;
- uncertain tokens rely more on TRELLIS prior and lower-confidence donor mixing.

## 8. Phase 3: Wan2.2 W-RFSDS Optimization

### 8.1 Teacher/student roles

Frozen teacher:

```text
Wan2.2 I2V-A14B DiT
Wan2.2 VAE weights
```

Trainable student variables:

```text
SS-RASA parameters
SLAT-RASA parameters
PartHead parameters
JointHead parameters
support gates
SLAT / Gaussian texture residuals
optional small latent residuals
```

### 8.2 Important gradient rule

Wan DiT teacher forward is no-grad.  
Wan VAE encode must remain differentiable with respect to the rendered video.

Correct conceptual flow:

```text
rendered video V_theta
  → Wan VAE encode, grad ON wrt V_theta
  → z
  → add RF noise z_tau
  → frozen Wan DiT predicts velocity, no_grad
  → residual gradient is injected into z
  → gradient flows back to render / TRELLIS adapters / texture variables
```

### 8.3 Optimization schedule

```text
Stage A: high/mid-noise W-RFSDS
  optimize part, joint, support, geometry

Stage B: low-noise W-RFSDS
  optimize SLAT-RASA, texture/detail, exposed surfaces
```

Wan2.2's high-noise / low-noise expert split provides a natural coarse-to-fine schedule.

## 10. Required Ablations

### 10.1 Input and conditioning

- no Wan pseudo-state conditions;
- K pseudo-state conditions as weak donors only;
- K pseudo-state conditions as full TRELLIS conditions;
- fixed-camera prompt vs unconstrained prompt.

### 10.2 SS modules

- no RASA;
- cached-hidden PAM;
- in-loop SS-RASA-Core;
- SS-RASA with / without part slots;
- SS-RASA with / without frame confidence;

### 10.3 SLAT modules

- no SLAT-RASA;
- 2D texture fusion fallback;
- K-way MCA only;
- K-way TFSA only;
- K-way MCA+TFSA;
- Slat-Merge disabled vs enabled.

### 10.4 Support and merging

- TRELLIS hard support only;
- fixed support without gate;
- fixed support with differentiable gate;
- soft base tying vs hard training copy;
- no NANO3D-style merge vs SS+SLAT merge.

### 10.5 RFSDS

- no W-RFSDS;
- geometry-only RFSDS;
- texture-only RFSDS;
- high-to-low noise schedule;
- low-noise only;
- Wan2.2 TI2V-5B PoC vs I2V-A14B final.

## 12. Main Novelty Claim

The intended AAAI-level contribution is:

> We transform a frozen static 3D generator, TRELLIS, into a single-image articulated asset generator by inserting RFSDS-optimized cross-state adapters inside its SS and SLAT generation stages. Wan2.2 supplies pseudo-state image conditions and a fixed-camera video prior; NANO3D-style SS/SLAT merging enforces base preservation; MorphAny3D-style SLAT attention fusion supplies cross-state texture consistency. The method optimizes only newly inserted modules and continuous latent variables, while preserving frozen TRELLIS and Wan2.2 backbones.

## 14. Non-Claims

We should not claim:

- TRELLIS already contains explicit articulated labels.
- Wan2.2 provides ground-truth part segmentation.
- `argwhere` is differentiable.
- K pseudo-state frames are real observations.
- MorphAny3D proves articulated texture fusion; it only motivates SLAT attention fusion.
- NANO3D solves articulation; it motivates region-aware preservation.

We should claim:

- TRELLIS has spatially localized, editable SLAT representations.
- K pseudo-state frames provide self-generated conditions from a single image.
- RASA adapters convert TRELLIS internal locality into base/move/joint structure.
- W-RFSDS optimizes newly inserted layers and continuous latent variables.
- Region-aware SS/SLAT merging gives architectural base preservation.
